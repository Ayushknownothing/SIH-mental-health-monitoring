# SIH Mental Health Monitoring System

## API Contract

**Project:** AI-Powered Dynamic Mental Health Monitoring and Distress Prediction System for Victims of Atrocities

**Version:** 1.0
**Status:** Prototype

---

## 1. Purpose

This document defines the communication contract between the React frontend, FastAPI backend, AI/ML pipeline, and Supabase database.

All components should follow these data structures during development and integration.

The numerical distress score is generated by the structured AI/ML pipeline. Llama is used only for natural-language explanation/conversation and does not determine the numerical distress score.

---

# 2. System Flow

```text
React Frontend
      |
      | HTTP / JSON
      v
FastAPI Backend
      |
      +----> RoBERTa Text Emotion Model
      |
      +----> Voice Stress Model
      |
      +----> ANN Distress Model
      |
      v
Feature Fusion + Prediction
      |
      +----> Explainability
      |
      +----> Llama Explanation
      |
      v
Supabase
      |
      v
Historical Data
      |
      v
React Dashboard
```

# 4. POST /checkin

## Purpose

Submit a new victim check-in containing text and optionally voice input.

Every successful check-in creates a new interaction. Previous interactions must never be overwritten.

## Request

```json
{
  "victim_id": "V001",
  "text": "I am scared and I don't feel safe.",
  "voice": null
}
```

### Fields

| Field     | Type        | Required | Description                                  |
| --------- | ----------- | -------: | -------------------------------------------- |
| victim_id | string      |      Yes | Unique victim identifier                     |
| text      | string      |    Yes\* | Victim's text response                       |
| voice     | string/null |       No | Audio reference or uploaded audio identifier |

`*` The prototype may support text-only or voice-only interaction later, but the initial implementation should support text input.

This endpoint may initially use dummy AI output while the real models are being developed.

# 6. Emotion Output

The text emotion model should return normalized probability values between `0` and `1`.

Example:

```json
{
  "fear": 0.91,
  "sadness": 0.32,
  "anger": 0.18,
  "nervousness": 0.84
}
```

The exact emotion feature set may be adjusted during implementation based on the actual labels available from the selected RoBERTa model.

Emotion classification must not be described as a clinical diagnosis.

---

# 7. Voice Stress Output

The voice model should produce a normalized stress indicator between `0` and `1`.

Example:

```json
{
  "voice_stress": 0.79
}
```

Voice stress is one feature in the overall prediction pipeline.

It must not independently determine the final distress score.

---

# 8. Distress Score

The ANN produces the final prototype distress score.

Range:

```text
0–100
```

Example:

```json
{
  "distress_score": 74
}
```

The model is trained using synthetic prototype data and is therefore not clinically validated.

---

# 9. Risk Classification

Prototype thresholds:

|  Score | Risk     |
| -----: | -------- |
|   0–25 | LOW      |
|  26–50 | MODERATE |
|  51–75 | HIGH     |
| 76–100 | CRITICAL |

These thresholds are prototype-defined and are not clinical or government standards.

---

# 10. Confidence

The system may return a confidence value between `0` and `1`.

Example:

```json
{
  "confidence": 0.87
}
```

Confidence should describe model/prediction confidence where technically meaningful.

It must not be presented as clinical certainty.

---

# 11. Trend

The system should compare the latest score with the previous recorded score.

Example:

```json
{
  "trend": {
    "direction": "INCREASING",
    "previous_score": 68,
    "change": 6
  }
}
```

Possible directions:

```text
INCREASING
DECREASING
STABLE
NO_PREVIOUS_DATA
```

Example:

```text
Previous: 68
Current: 74
Change: +6
Direction: INCREASING
```

---

# 12. Explainability

The prediction response should contain the major contributing indicators.

Example:

```json
{
  "contributors": [
    {
      "feature": "fear",
      "value": 0.91
    },
    {
      "feature": "nervousness",
      "value": 0.84
    },
    {
      "feature": "voice_stress",
      "value": 0.79
    }
  ]
}
```

The frontend may display these as bars, cards, or another simple visualization.

The exact XAI technique may be implemented using feature contribution, permutation importance, SHAP, or another practical approach.

# 17. Important Integration Rules

### Rule 1

Llama must not calculate:

```text
distress_score
```

The ANN produces it.

### Rule 2

Previous predictions must never be overwritten.

### Rule 3

Every check-in should receive a unique interaction ID in the database.

### Rule 4

Emotion values and voice stress should be normalized to `0–1`.

### Rule 5

Distress score should be normalized to `0–100`.

### Rule 6

The frontend should consume the API response rather than directly accessing AI models or Supabase.

### Rule 7

The AI module should not depend on React.

### Rule 8

The backend acts as the primary integration layer between frontend, AI and database.

### Rule 9

Dummy AI responses may be used during parallel development.

### Rule 10

The prototype must be described as a synthetic-data-based distress estimation system, not a clinically validated diagnostic system.

---

# 18. Prototype Disclaimer

The system is a technical prototype intended to demonstrate dynamic distress estimation and monitoring.

The model is trained/evaluated using synthetic or limited prototype data and has not been clinically validated.

Predictions should therefore be treated as indicators for demonstration and potential support prioritization, not as medical diagnoses.
